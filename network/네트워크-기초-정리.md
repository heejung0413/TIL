# 네트워크 기초 정리

회사 유선 네트워크 설정 화면에 입력한 값을 예시로, IP 주소·서브넷 마스크·라우터·DNS가 각각 무슨 일을 하는지 정리한 문서입니다.

## 1. 내 설정 값

| 항목 | 값 | 한 줄 설명 |
| --- | --- | --- |
| IP 주소 | `10.52.2.179` | 내 PC 한 대의 주소 |
| 서브넷 마스크 | `255.255.255.0` | IP 주소에서 어디까지가 네트워크 부분인지 알려 주는 값 |
| 라우터 | `10.52.2.1` | 다른 네트워크로 나갈 때 거치는 출입구 |
| DNS 서버 | `8.8.8.8` | 도메인 이름을 IP 주소로 바꿔 주는 서버 (구글 운영) |

이 값들로 계산되는 것:

| 항목 | 값 |
| --- | --- |
| 네트워크 주소 | `10.52.2.0` |
| 같은 네트워크 범위 | `10.52.2.0` ~ `10.52.2.255` |
| 기기에 줄 수 있는 주소 | `10.52.2.1` ~ `10.52.2.254` (254개) |

## 2. IP 주소

- 네트워크에 연결된 **기기 한 대**의 주소입니다. PC, 휴대폰, 공유기, 라우터가 각각 하나씩 가집니다.
- `10.52.2.179`는 전산팀이 내 PC에 지정한 주소입니다.
- 주소를 받는 방법은 두 가지입니다.

| 방식 | 설명 | 쓰는 곳 |
| --- | --- | --- |
| 자동(DHCP) | 연결하면 공유기나 서버가 비어 있는 주소를 알아서 줌 | 집 와이파이 |
| 수동 | 전산팀이 정해 준 값을 직접 입력 | 회사 유선 (지금 내 설정) |

수동으로 하면 IP가 바뀌지 않아서, "이 IP는 이 서버에 접근 허용" 같은 방화벽 규칙을 유지하기 쉽습니다.

## 3. 서브넷 마스크

### 3.1 하는 일

IP 주소는 **네트워크 부분 + 호스트 부분**으로 이루어져 있습니다. 마스크는 그 경계가 어디인지 알려 줍니다.

```
IP 주소      10 . 52 . 2 . 179
마스크      255 .255 .255.   0
            └── 네트워크 ──┘ └ 호스트 ┘
```

- 마스크가 `255`인 자리: 네트워크 부분 (어느 묶음인지)
- 마스크가 `0`인 자리: 호스트 부분 (그 묶음 안의 몇 번 기기인지)

### 3.2 계산 방법

**내 IP 주소**와 마스크를 비트 단위로 AND 하면 네트워크 주소가 나옵니다.

```
IP      00001010.00110100.00000010.10110011   (10.52.2.179)
마스크  11111111.11111111.11111111.00000000   (255.255.255.0)
AND     00001010.00110100.00000010.00000000   (10.52.2.0)  ← 네트워크 주소
```

### 3.3 왜 필요한가

네트워크마다 크기가 달라서 경계 위치가 고정이 아닙니다. 그래서 IP 주소만 봐서는 어디까지가 네트워크 부분인지 알 수 없고, 마스크가 따로 있어야 합니다.

내 PC는 데이터를 보낼 때마다 이 마스크로 판단합니다.

| 상대 IP | 판단 | 보내는 방법 |
| --- | --- | --- |
| `10.52.2.50` | 나와 같은 네트워크 | 상대에게 직접 보냄 |
| `10.52.3.50`, `8.8.8.8` 등 | 다른 네트워크 | 라우터(`10.52.2.1`)에게 넘김 |

이 판단은 **보내는 PC가** 합니다. 누가 보냈는지 구분하는 용도가 아닙니다(그건 IP 주소가 합니다).

### 3.4 마스크와 기기 수

IP 주소는 32비트로 길이가 고정이라, 네트워크 부분을 늘리면 호스트 부분이 줄어듭니다. 그래서 마스크가 한 네트워크에 넣을 수 있는 기기 수를 정합니다.

| 마스크 | 호스트 비트 | 넣을 수 있는 기기 |
| --- | --- | --- |
| `255.255.255.128` | 7비트 | 126대 |
| `255.255.255.0` (지금 설정) | 8비트 | 254대 |
| `255.255.254.0` | 9비트 | 510대 |
| `255.255.0.0` | 16비트 | 65,534대 |

- 계산식: `2^호스트 비트 수 - 2`
- 2를 빼는 이유: 맨 앞 주소(`10.52.2.0`, 네트워크 이름)와 맨 뒤 주소(`10.52.2.255`, 전체에게 한꺼번에 보내는 브로드캐스트 주소)는 기기에 줄 수 없습니다.

기기가 254대보다 많으면:

1. **네트워크를 여러 개 만든다.** `10.52.3.x`, `10.52.4.x`를 추가하고 라우터로 잇습니다. 회사는 보통 이 방식으로 부서·층별로 나눕니다.
2. **마스크를 바꿔 한 네트워크를 키운다.**

마스크는 내 PC에서 혼자 바꾸면 안 됩니다. 같은 네트워크의 모든 기기와 라우터가 같은 값을 써야 하므로 전산팀이 정합니다. 내 PC만 `255.255.0.0`으로 바꾸면 `10.52.3.x`도 같은 네트워크라고 착각해 라우터에 넘기지 않고 직접 보내려다 통신이 안 됩니다.

## 4. IP 주소와 네트워크 주소의 차이

| | IP 주소 | 네트워크 주소 |
| --- | --- | --- |
| 가리키는 것 | 기기 한 대 | 기기 묶음 전체 |
| 내 값 | `10.52.2.179` | `10.52.2.0` |
| 어디서 오나 | 전산팀이 할당 | IP 주소와 마스크로 계산 (따로 받지 않음) |
| 기기에 할당 | 함 | 안 함 |

- 네트워크 주소는 IP 주소 안에 들어 있는 앞부분입니다.
- 유선으로 연결했다고 모두 같은 네트워크 주소를 쓰는 것은 아닙니다. 같은 대역끼리만 같고, 회사는 대역을 여러 개로 나눠 씁니다.
- 라우터도 "이 네트워크 주소는 어느 방향"이라는 표를 보고 길을 정하므로, 라우터를 거치는 통신에도 네트워크 주소가 쓰입니다.

## 5. 라우터 (게이트웨이)

- 내 네트워크와 다른 네트워크를 잇는 **출입구**입니다. 아파트 단지의 정문과 같습니다.
- "게이트웨이"는 역할 이름이고, 그 역할을 하는 장비가 라우터입니다.
- 라우터 주소(`10.52.2.1`)는 반드시 **내 네트워크 안**에 있어야 합니다. 내 PC가 직접 닿을 수 있어야 데이터를 넘길 수 있기 때문입니다.
- 라우터 주소를 설정하지 않으면 같은 네트워크(`10.52.2.x`)끼리는 통신되지만, 인터넷이나 다른 부서 대역으로는 나가지 못합니다.

| | 게이트웨이 역할을 하는 장비 |
| --- | --- |
| 집 | 공유기 (게이트웨이 + 무선 AP + 스위치 + DHCP 서버를 한 대가 겸함) |
| 회사 | 전산실의 라우터·방화벽 장비 |

## 6. DNS 서버

- 사람은 `naver.com` 같은 이름을 쓰지만 컴퓨터는 IP 주소로만 통신합니다. DNS 서버는 **이름을 IP 주소로 바꿔 주는 전화번호부**입니다.
- 순서: 브라우저에 `naver.com` 입력 → 내 PC가 `8.8.8.8`에 "naver.com의 IP가 뭐야?" 질문 → IP를 받음 → 그 IP로 접속
- `8.8.8.8`은 구글이 인터넷에 공개해 둔 DNS 서버입니다. 회사 안에 있는 장비가 아니라서, 질문도 라우터를 거쳐 밖으로 나갑니다.

| 주소 | 운영 |
| --- | --- |
| `8.8.8.8` | 구글 |
| `1.1.1.1` | 클라우드플레어 |
| `168.126.63.1` | KT |

- 집 와이파이는 DNS를 직접 입력하지 않아도 됩니다. 공유기가 IP를 줄 때 DNS 주소도 같이 알려 주고, 보통 통신사 DNS로 연결됩니다.
- DNS 설정은 연결(유선·와이파이)마다 따로 있습니다.

## 7. 유선 네트워크 동작 원리

1. **랜선**: 데이터를 전기 신호로 보냅니다.
2. **MAC 주소**: 랜 어댑터마다 공장에서 박혀 나오는 고유 번호입니다. 같은 네트워크 안에서 실제 배달은 이 번호로 합니다.
3. **스위치**: 랜선이 모이는 장비입니다. 받은 데이터의 MAC 주소를 보고 해당 기기가 꽂힌 포트로만 전달합니다.
4. **ARP**: IP 주소만 알고 MAC 주소를 모를 때, 네트워크 전체에 "이 IP 쓰는 분 누구세요"라고 물어 MAC 주소를 알아내는 절차입니다.

보내는 흐름:

- **같은 네트워크** (`10.52.2.50`): ARP로 상대의 MAC 확인 → 스위치가 상대 포트로 전달
- **다른 네트워크** (`8.8.8.8`): ARP로 **라우터**의 MAC 확인 → 라우터에게 전달 → 라우터가 다음 길로 보냄

## 8. 방화벽과 GitLab 접근 제한

- 방화벽은 요청의 **출발지 IP**를 보고 통과 여부를 정합니다.
- 방화벽 신청서에 IP와 서브넷 마스크를 함께 적는 이유는 허용 범위를 정하기 위해서입니다.

| 표기 | 허용 범위 |
| --- | --- |
| `10.52.2.179` + `255.255.255.255` (/32) | 이 PC 한 대 |
| `10.52.2.0` + `255.255.255.0` (/24) | `10.52.2.x` 대역 전체 |

- 회사 GitLab이 회사 네트워크에서만 열리는 것도 출발지 IP 기준입니다. VPN은 밖에 있는 PC가 회사 내부 IP로 출발하는 것처럼 만들어 줍니다.
- 방화벽(어디서 왔는지 확인)과 로그인(누구인지 확인)은 별개의 단계입니다.
- 회사의 실제 방화벽 설정이나 신청서 처리 방식은 전산팀에 확인해야 합니다.

## 9. 사설 IP와 공인 IP

- `10.x.x.x`, `172.16.x.x`~`172.31.x.x`, `192.168.x.x`는 **사설 IP**입니다. 내부 전용이라 다른 회사·집에서 같은 주소를 써도 충돌하지 않습니다. 아파트마다 101호가 있는 것과 같습니다.
- 사설 IP는 인터넷에서 통하지 않습니다. 밖으로 나갈 때 라우터가 출발지 주소를 회사의 **공인 IP**로 바꿔 줍니다(NAT). 여러 PC가 공인 IP 하나를 같이 쓰고, 포트 번호로 누구의 통신인지 구분합니다.
- 공인 IP(IPv4)는 약 43억 개뿐이라 부족합니다. 그래서 NAT로 아껴 쓰고, 통신사도 가입자 여럿을 공인 IP 하나로 묶으며, 주소가 훨씬 많은 IPv6로 옮겨 가는 중입니다.

## 10. 헷갈렸던 점

| 헷갈린 생각 | 실제 |
| --- | --- |
| 네트워크 주소에 마스크를 AND 한다 | **내 IP 주소**에 AND 한다. 결과가 네트워크 주소 |
| IP 주소는 공유기의 주소다 | 기기마다 하나씩 있다. 공유기도 그중 한 대 |
| 마스크로 어떤 직원인지 구분한다 | 구분은 IP 주소가 한다. 마스크는 직접 보낼지 라우터에 넘길지 판단하는 용도 |
| 유선이면 네트워크 주소가 모두 같다 | 같은 대역끼리만 같다. 회사는 부서·층별로 나눈다 |
| 마스크는 어디까지가 IP 주소인지 알려 준다 | 어디까지가 **네트워크 부분**인지 알려 준다 |
| 라우터를 거치니 네트워크 주소는 필요 없다 | 같은 네트워크끼리는 라우터를 안 거치고, 라우터도 네트워크 주소로 길을 정한다 |

## 11. 맥에서 확인하는 명령

| 확인할 것 | 명령 |
| --- | --- |
| 내 IP 주소와 마스크 | `ifconfig \| grep "inet "` |
| 라우터 주소 | `netstat -nr \| grep default` |
| 쓰고 있는 DNS 서버 | `scutil --dns \| grep nameserver` |
| 이름이 IP로 바뀌는지 | `nslookup naver.com` |
| 라우터까지 닿는지 | `ping 10.52.2.1` |
| 내 MAC 주소 | `ifconfig \| grep ether` |
| 같은 네트워크 기기의 IP와 MAC | `arp -a` |
| 밖에서 보이는 공인 IP | `curl ifconfig.me` |
